# 챔피언 표시명 캐시 검증

## 변경

성공한 비어 있지 않은 DataDragon 맵에 조회 완료 시점부터 24시간의 메모리 만료를 적용했다.
만료 전 읽기는 수명을 늘리지 않으며, 만료 시각부터 다음 조회에서 다시 로드한다.
같은 모듈 인스턴스의 동시 최초 조회·갱신은 진행 중인 Promise를 공유하고 각 호출은 요청한
이름만 담은 독립 결과 맵을 받는다.

기존 두 요청과 본문 처리 전체의 2초 제한, 원격 응답 검증, 내부 이름 폴백과 Next.js fetch의
하루 재검증 설정은 유지했다. 실패·빈 응답·타임아웃 후에는 다음 호출에서 다시 시도할 수 있다.
타임아웃 이후 도착한 응답은 캐시나 새 조회에 영향을 주지 않는다.

## 로컬 증거

- 새 회귀 8개를 기존 구현에서 실행해 모두 실패하는 것을 확인했다. 최초 동시 조회 10개는
  모의 fetch 20회를 호출했고, 만료된 맵은 갱신하지 않았다.
- 수정 후 `champions.test.ts` 16개가 모두 통과했다. 24시간 경계, 조회 완료 기준 만료,
  갱신 후 수명, 동시 최초 조회·갱신, 호출 결과 격리, 오류·HTTP 실패·빈 맵·잘못된 응답 후
  복구와 타임아웃 이후 늦은 응답이 새 조회에 영향을 주지 않는지 확인했다.
- Node.js 24.21.0에서 `npm run check`를 통과했다. 45개 파일 중 42개 통과·3개 건너뜀,
  전체 800개 테스트 중 749개 통과·51개 건너뜀이며 lint·typecheck·build·format도 통과했다.
- `openspec validate --all --strict`에서 변경 13개가 모두 통과했다.

## 독립 리뷰

서브에이전트 두 명이 순차적으로 독립 리뷰했으며, 두 차례 모두 수정이 필요한 문제를
발견하지 않았다. 첫 리뷰는 코드·테스트·OpenSpec의 만료·동시성·실패 복구 계약을 대조하고
챔피언 테스트 16개와 변경 명세 strict 검증을 통과했다.

두 번째 리뷰는 실제 페이지 호출 경로와 설치된 Next.js fetch 문서·재검증 구현도 확인했다.
Node.js 26.5.0에서 기존 16개와 임시 회귀 8개를 실행해 모두 통과했다. 임시 회귀는 만료 후
타임아웃, 새 조회 진행·완료, 이전 헤더·본문의 늦은 성공·실패 조합에서 새 캐시와 진행 중인
조회가 보존되는지 검증했으며 검증 후 제거했다. 최종 코드와 영구 테스트는 위 Node.js 24
전체 검사 이후 변경하지 않았다.

## 검증 범위

챔피언 조회는 모의 fetch와 가상 시계를 사용했다. 실제 DataDragon 연결, Next.js Data Cache의
런타임 재검증, 여러 Vercel 인스턴스의 외부 호출 수와 운영 배포는 검증하지 않았다.
메모리의 24시간 만료를 외부 원본의 24시간 이내 최신성 보장으로 해석하지 않는다.

Redis·PostgreSQL·실제 리플레이 전용 환경을 지정하지 않아 해당 테스트 51개를 건너뛰었다.
이번 변경은 DB·Redis·인증 로직과 스키마를 수정하지 않는다.
