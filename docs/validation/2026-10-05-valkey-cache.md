# 2026-10-05 Valkey 조회 캐시와 닉네임 검색 기반 검증

이 기록은 자동완성·검색 화면 연결 이전의 조회 캐시·검색 기반 검증입니다.
현재 사용 흐름과 인덱스 운영은 [Valkey 안내](../valkey.md#조회-캐시와-닉네임-검색)를 참고하세요.
아래 629개 테스트 결과와 당시의 비활성 검색 UI 설명은 해당 시점의 기록으로 유지합니다.

## 실행 환경

- Podman 5.7.1, 로컬 `127.0.0.1:16379` → 컨테이너 6379.
- 공식 `docker.io/valkey/valkey:9`, 실제 `valkey_version:9.1.2`.
- 이미지 digest: `sha256:418652cfb58ef879d4978c33553735d7147016032d5aefaa14c828e611eb9dfd`.
- 클라이언트 `ioredis 6.0.0`. 영속 볼륨 없이 실행한 일회용 컨테이너.
- PostgreSQL은 실제 저장소 마이그레이션을 적용한 메모리 PGlite. 인증은 테스트 전용 키와 실제 서명 세션.
- 운영 `VALKEY_URL`은 사용하지 않고 테스트 전용 `LLVY_VALKEY_TEST_URL`로만 연결.

## 결과

최종 `npm run check`에서 **33개 파일, 629개 테스트가 모두 통과**했다. Podman Valkey 통합 테스트
17개와 연결 설정·제한 시간 테스트 9개, 기존 실제 리플레이 테스트를 포함했다.
ESLint·TypeScript·Next.js 빌드·Prettier도 통과했다.
`openspec validate --all --strict`는 7개 변경을 통과했고 `git diff --check`도 통과했다.

캐시 적중·NULL 결과, 실제 TTL과 만료, 역할·인자별 키, 손상된 JSON·큰 결과의 직접 조회,
느린 조회와 세대 무효화 경쟁, 세대 키 제거 후 재생성을 검증했다.
모임원 수정·삭제, 계정 연결·해제, 게임 코멘트·날짜·제외·복구와 신규 리플레이 저장 후
캐시가 갱신되고, 중복 리플레이와 롤백은 기존 세대를 유지했다.

일반 사용자용 캐시에는 원문 모임원 이름과 생년 필드가 없었다. 오너가 채운 결과와 키를
공유하지 않으며, 미인증·취소된 관리자 세션은 캐시 조회 전에 거부됐다.
연결 거부와 캐시 명령 오류는 DB 조회로 돌아갔고, 무효화 실패 후에도 이미 완료한 DB 변경은
성공으로 유지됐다. 연결이 완료되지 않는 드라이버에 대해 1초 대기 상한도 검증했다.

닉네임·선택적 태그, 대소문자·NFC·공백 정규화, `%`·`_`·역슬래시의 문자 그대로 일치,
제외 경기만 있는 계정 제거, 20개 결과 상한과 조회자 이름 마스킹을 검증했다.
랜딩의 검색 버튼은 비활성 상태를 유지하고 공개 검색 API는 추가하지 않았다.

## 실행 명령

```bash
VALKEY_URL="" \
LLVY_VALKEY_TEST_URL="redis://127.0.0.1:16379" \
LLVY_REPLAY_FILE="/absolute/path/to/match.rofl" \
npm run check

openspec validate --all --strict
git diff --check
```

처음 추가한 장애 주입 테스트 2개는 비동기 소켓 종료와 테스트 정리가 겹쳐 정리 단계에서
실패했다. 정리 시 새 연결로 해당 UUID 키 공간만 제거하도록 수정했고 최종 전체 검사에서 통과했다.

## 증거의 범위

이 기록은 로컬 Valkey 9.1.2 명령과 캐시·조회 기능의 검증이다. 실제 Layerbase DB의 세부 버전,
TLS 인증서·네트워크·휴면 복귀·Vercel 연결 수는 검증하지 않았고 앱을 배포하지 않았다.
실제 연결은 [Valkey 배포 후 확인](../valkey.md#배포-후-확인)에서 수행한다.
기존 운영 배포 검증 기록을 이번 변경의 배포 증거로 사용하지 않는다.
