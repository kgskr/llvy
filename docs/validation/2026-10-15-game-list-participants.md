# 게임 목록 참여자 표시 검증 — 2026-10-15

## 변경

- 전체 기록과 제외된 경기를 10경기씩 표시하며, 인원 칸을 팀별 두 줄 참여자 목록으로 바꿨다.
- 블루 승리 `#28344e`, 레드 승리 `#59343b` 배경을 로우 전체에 적용하고 결과 미확인은 중립색으로 표시한다.
- 연결된 참가자는 모임원 이름, 미연결 계정은 라이엇 ID를 표시한다. 이름 왼쪽에 24px 초상화를 넣고 정글은 `JUG`로 표기한다.
- 경기 페이지를 먼저 읽고 해당 경기 ID의 최소 참가자 정보를 한 번에 조회한다. 기존 요약 DTO는 유지하고 `game-list-v2` 캐시 키로 새 형식을 분리했다.
- 링크 자동 prefetch를 끄고, 페이지·보기 상태를 담은 상세 링크와 권한별 복구 기능을 유지한다.

## 검증 결과

- Node 24.21.0 전체 테스트: 797 통과, 50 건너뜀. 실제 리플레이 파일을 지정했고 worker는 4개로 제한했다.
- 관련 화면·권한·개인정보·DB 회귀: 69 통과.
- 임시 로컬 Redis 7 테스트: 52 통과. 이전 캐시 형식 격리, 캐시 적중 시 참가자 조회 생략, 모임원 이름 변경·연동 해제·재연동·삭제 이후 갱신과 미인증 접근 차단을 확인했다. 컨테이너는 종료·제거했다.
- PGlite에서 12경기를 준비하고 날짜 수정·경기 제외 후 첫 10경기, 나머지 페이지, 제외된 경기, 빈 페이지를 검증했다. 비어 있지 않은 페이지는 경기 1회·참가자 1회이며 참가자 쿼리의 ID가 현재 페이지와 일치한다. 빈 페이지는 참가자 조회가 없다. 개수 조회는 읽기 모델의 별도 1회다.
- 참가자 SELECT와 반환 DTO에서 원본 통계·PUUID·생년을 제외했고, 기존 전체 집계와 목록 DTO 회귀도 통과했다.
- lint, typecheck, production build, format 통과. OpenSpec 전체 strict validation 23 통과, git diff 공백 검사 통과.
- 실제 Next 개발 서버에서 합성 데이터를 사용해 컴포넌트를 확인했다. 1280px에서 초상화 30개가 로드됐으며 로우 배경은 지정한 RGB 값과 일치했다. 390px·320px에서 가로 넘침이 없고 긴 이름을 줄바꿈했다. 임시 미리보기 경로·서버를 제거했고 production build에 해당 경로가 없는 것을 확인했다.
- React 점검: 목록은 서버 컴포넌트이며 이미지 오류·기존 복구 폼만 클라이언트 경계를 사용한다. 이름/이미지 조회는 공유 캐시를 병렬로 요청하고, 참가자가 없으면 카탈로그 조회를 생략한다.

## 검증 범위

운영 DB 지연·쿼리 계획, 인증된 운영 화면, 배포는 확인하지 않았다. 쿼리 수와 캐시 동작은 로컬 검증 결과다. 화면 확인에는 실제 개인정보가 아닌 합성 데이터를 사용했다.
