## 로컬 처리 흐름 검증

`LLVY_REPLAY_FILE` 환경변수와 `npm run test:replay`로 다음 4개 테스트가 통과했다.

1. 실제 `/api/process` → 업로드 바인딩 검증·상태 변경 → 파싱 → 트랜잭션 저장 → 게임 목록·상세 조회.
   실제 SQL 마이그레이션을 적용한 PGlite에 게임 1개·계정 10개·참가자 10개가 저장되며,
   원본에서 파싱한 참가자 필드와 조회 결과가 일치한다. 파일 수정 시각과 `file_mtime` 출처를 보존한다.
2. 새 바인딩으로 동일 파일을 다시 처리하면 기존 게임 ID와 `duplicate: true`를 반환한다.
   게임·계정·참가자 수가 늘지 않고 원래 Blob URL을 보존한다. 삭제 호출은 중복 업로드 URL만 대상으로 한다.
3. 이미 사용한 바인딩을 다시 처리하면 409로 거부하며 추가 다운로드·삭제를 하지 않는다.
4. 파일 시각이 없으면 처리 시각과 `upload` 출처를 저장한다. 저장 후 계정을 모임원에 연결하면
   기존 게임 조회에 모임원이 반영되며 재수집하지 않는다.

인증 성공과 Blob 다운로드·삭제는 모의 처리했다. 다운로드 응답에는 실제 원본 bytes를 사용하고,
DB 어댑터를 제외한 업로드 바인딩·파서·저장·조회 로직은 앱 구현을 그대로 실행했다.
테스트 DB는 메모리에서만 유지되며 종료 시 닫는다.

수정 후 실파일 경로를 지정한 `npm run check`도 통과했다: 14개 테스트 파일의 212개 테스트,
ESLint, TypeScript, 프로덕션 빌드, Prettier 검사 모두 성공했다. 이 중 실파일 테스트는 4개이며,
경로를 지정하지 않은 일반 실행에서는 해당 4개를 건너뛴다. OpenSpec strict 검증도 통과했다.
