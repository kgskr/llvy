# 모임원 관계 통계 검증 — 2026-10-15

## 변경

- 플레이 포지션 바로 아래에 같은 팀 최고 승률, 상대 팀 최고 승률, 가장 많이 함께한 팀원, 가장 많이 만난 상대를 이 순서로 한 행에 표시한다. 없는 항목은 블록을 생성하지 않으며 모두 없으면 설명까지 생략한다.
- 연결된 모임원별로 계정을 합산하고 같은 팀/상대 팀 각각 3경기 이상인 후보를 사용한다. 기준 모임원 관점의 승률을 계산하며 미정은 만남 횟수에만 포함한다. 제외 경기, 불명 팀, 양쪽 중 한 사람의 중복 계정 참가는 해당 관계에서 제외한다.
- 승률 동률은 결정 경기 수, 전체 경기 수, 회원 UUID 순으로 결정한다. 횟수 동률은 회원 UUID 순이다. 승률 0%도 유효하다.
- 기존 인덱스로 기준 회원 경기부터 조회하는 단일 SQL이 최대 네 행만 반환한다. 이름과 필요한 집계 값만 투영한다.
- `member-relationships-v1` 캐시는 members/accounts/history revision과 aggregate TTL을 사용한다. 기존 전체·챔피언·포지션 캐시의 history 의존성을 유지해 이름 변경 시 관계 통계만 다시 계산한다. DB migration과 운영 캐시 활성 상태 변경은 없다.

## 검증

- 최종 검사는 프로젝트 기준인 Node 24.21.0에서 `LLVY_REDIS_TEST_URL`, `LLVY_POSTGRES_TEST_URL`, `LLVY_CACHE_BENCHMARK=1`을 설정한 `npm run check`로 실행했다. 폐기 가능한 로컬 Redis 7과 PostgreSQL 17을 사용해 55개 파일·886개 검사 통과, 개인 리플레이 4개 검사 건너뜀을 확인했다. lint/typecheck/build/format도 모두 통과했다.
- 초기 Node 26.5.0 검사(873개 통과, 17개 건너뜀) 이후 리뷰에서 런타임 보완 의견이 있어 위 Node 24 최종 검사로 재확인했다. 실제 PostgreSQL 동시성 12개와 선택적 캐시 workload도 최종 검사에 포함했다.
- 관계 집계·기존 전적·권한·개인정보·새 블록 렌더링의 집중 검사 85개 통과. 관계별 2/3경기 경계, 양쪽 다중 계정 합산, 페이지 독립성, 제외/불명/중복 참가, 본인 관점의 상대 승률, 미정만 있는 관계와 0% 승률, 동률 순위를 확인했다.
- SQL 호출 spy로 관계 집계가 한 번의 질의로 실행되고, Redis hit와 다음 페이지에서 반복되지 않음을 확인했다. 이름 수정 시 관계 이름은 갱신되지만 기존 챔피언 집계는 재실행되지 않는다. 경기 제외/복원, 연결 해제/복구, 회원 삭제 후 후보 갱신을 확인했다.
- 실제 `getMemberRelationshipHighlights()`를 임시 harness로 불러와 PostgreSQL 17.11에서도 16개 검사를 통과했다. 네 항목 선정, 관계별 3경기 기준, 소수·0% 승률, 미정, 제외·중복·불명 참가를 확인했다. 단일 연결의 `BEGIN/ROLLBACK` 뒤 테이블별 행 수 복원과 생성 회원 제거를 검증했다.
- 실제 서버 컴포넌트와 CSS로 만든 합성 HTML을 인앱 브라우저에서 확인했다. 1,100px 화면은 네 블록 모두 y=173, 너비 251px로 한 행이다. 360px 화면은 네 블록 모두 y=173, 너비 190px이며 행 내부만 가로 스크롤된다(행 312px/내용 808px, 문서 360px). 블록 하나는 행 너비 1,052px를 채우고, 후보가 없으면 블록과 영역이 모두 0개다.
- OpenSpec 전체 strict 검사: 25개 통과. `git diff --check` 통과.

## 독립 리뷰

- 1차: SQL·집계, 캐시·권한, 화면·문서를 분담한 서브에이전트 3명 모두 수정이 필요한 코드 지적 0건이었다. Node 24 검증 보완 의견은 위 최종 검사로 해소했다.
- 2차: 같은 세 영역을 독립적으로 다시 검토해 모두 지적 0건을 확인했다. SQL 담당은 실제 PostgreSQL에서 관계 집계 함수를 추가 검증했고, 캐시·화면 담당은 최종 소스와 갱신된 검증 기록까지 재확인했다. 미해결 지적은 없다.

## 검증 범위

관계 집계 회귀 검사는 폐기 가능한 로컬 PGlite, 관계 SQL 추가 검증과 인증 동시성 검사는 로컬 PostgreSQL 17, 캐시는 로컬 Redis 7을 사용했다. 화면은 실제 컴포넌트로 만든 합성 미리보기이며 인증된 운영 페이지나 운영 데이터 검증이 아니다. 개인 리플레이 파일이 없어 관련 검사 4개는 생략했다. 운영 DB/배포/Discord/Blob/Cron은 이번에 검증하거나 변경하지 않았다.
