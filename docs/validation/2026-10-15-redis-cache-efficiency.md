# Redis 캐시 개선 검증 — 2026-10-15

## 변경과 기준

- 기준은 `ce74eaa`이며 직전 `edd10f7`의 경기 목록 10개, 전적 25개, 참가자·레벨·아이템 DTO를 유지한다. 페이지 참가자 1회 조회와 에셋 공동 로딩도 유지한다.
- PostgreSQL revision을 업무 변경과 함께 커밋하고 역할·epoch·의존 범위를 Redis 키에 반영한다. 모임원 목록과 포함된 연결 계정은 jitter 없이 86,400초, 나머지는 이름 붙인 정책을 사용한다.
- 전적 계정·집계·페이지를 분리하고 동일 miss를 합친다. 자동완성은 두 읽기를 pipeline으로 묶고 독립 프로세스 lease, 소유권 확인 게시, `after()` 게시와 누락 복구를 적용한다.
- 정책은 기본 비활성이다. 운영 migration·활성화와 코드 구현의 완료 상태를 구분한다.

## 고정 workload 측정

실제 Redis 7 + PGlite, 합성 전적 한 페이지, 제어한 시계로 2분 간격 30회 재방문했다.
기준은 기존 60초 전체 전적 캐시 로딩과 같으며, 새 경로는 인증·신원·revision SQL을 포함한다.
카탈로그 호출·HTTP·Neon 네트워크·Vercel 실행 시간은 포함하지 않았다.

| 측정                              | 기존 60초 | revision/분리 캐시 |
| --------------------------------- | --------: | -----------------: |
| 집계·경기 페이지 SQL              |       120 |                  5 |
| 전체 SQL(인증·신원·revision 포함) |       240 |                100 |
| p50                               |    5.90ms |             1.49ms |
| p95                               |    7.44ms |             3.45ms |
| Redis 명령                        |        93 |                 97 |

집계·페이지 SQL은 95.8% 감소했다. 일반 SQL 전체 감소율과 혼동하지 않는다.
두 경로를 함께 실행한 fixture 캐시 4개는 3,872바이트였다. 운영 최대 메모리 추정치가 아니다.
실제 서비스 호출이 없는 호환용 부분 검색 API는 5분 정책으로 보존한다.
10,000행·8MiB 게시 상한과 10초 lease는 초기 보호값이며 운영 분포·build p95로 재평가한다.

## 배포 범위

작업 중 확인한 production은 기준 커밋의 READY 배포였고, 이전 production·preview 배포들도 남아 있었다.
모든 이전 writer의 사용 중단을 입증하지 않았으므로 운영 장기 캐시를 임의 활성화하지 않는다.
운영 backup/disposable branch migration 검증, 정책 활성화, 인증된 배포 smoke·반복 timing은 별도 전환 작업으로 남긴다.
이 파일의 숫자는 로컬 증거이며 운영 캐시 적중률·응답 시간·외부 제공자 검증으로 해석하지 않는다.

## 완료 기록

- 독립 서브에이전트 3개가 변경 일관성, 캐시 런타임, DTO·권한·명세를 리뷰했다.
- 1차 지적: 기존 legacy 계정의 관측 시각만 갱신해도 accounts revision을 증가시키던 경로를 수정했다.
- 2차 지적: 수정 중 분리했던 INSERT/UPDATE 사이의 PUUID 승격 경합을 실제 PostgreSQL에서 재현하고 제거했다.
- 최종 구현은 단일 원자 upsert를 유지하며 삽입용 UUID와 반환 ID 비교로 신규 생성만 판별한다.
  영구 회귀는 timestamp-only 갱신의 revision 불변, 신규 생성의 증가, 동시 승격의 행 잠금 대기와 동일 계정 유지까지 검증한다.
- 3차 리뷰: 세 리뷰어 모두 추가 actionable finding 없음. 한 리뷰어의 독립 재실행은 5파일 95개 통과했다.
- 최종 전체 검사 54파일 867개와 OpenSpec 24개, diff 공백 검사 통과. 운영 활성화 완료를 의미하지 않는다.
