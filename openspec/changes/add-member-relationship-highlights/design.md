## Context

기존 회원 상세는 전체 전적을 페이지와 독립적으로 집계하고 Redis 집계 캐시를 사용한다. 계정 연결을 통해 사람을 식별하며 참가자 수는 경기당 최대 10명이다. 사용자 요청은 플레이 포지션 바로 아래의 단일 행과 빈 블록 생략이다.

## Goals / Non-Goals

**Goals:** 관계별 3경기 이상 후보의 최고 승률·최다 만남을 정확하게 집계하고 최대 네 블록으로 표시한다.

**Non-Goals:** 미연결 계정을 사람으로 추정, 전체 회원 간 순위표, DB 스키마 변경, 운영 캐시 정책 활성화.

## Decisions

- 기준 회원의 활성 경기부터 조회하는 SQL 한 개로 상대별 같은 팀/상대 팀 전적을 집계한다. 양쪽 모두 그 경기에 연결된 계정이 정확히 하나이고 팀이 100/200인 경우만 사용한다. 조건을 적용하기 전에 계정 수를 세어 불명 팀을 가진 중복 계정도 모호함으로 판정한다.
- 관계별 전체 경기 수가 3 이상인 후보만 인정한다. 승패 미정은 만남 횟수에 포함하되 승률 분모에서 제외한다. 결정된 경기가 없는 후보는 최다 만남에만 참여한다. 승률은 기준 회원 관점이다.
- 같은 모임원의 여러 계정을 합산하고 미연결 계정과 본인은 제외한다. 승률은 반올림하지 않은 비율, 결정 경기 수, 전체 경기 수, 회원 UUID 순으로 정렬한다. 최다 만남은 전체 경기 수, 회원 UUID 순이다. 각 항목은 한 명만 반환하며 최대 네 행이다.
- 관계 통계는 `member-relationships-v1` 키의 독립 집계 캐시에 넣고 `members`, `accounts`, `history` revision을 반영한다. 이름/연결 변경 후 이전 결과를 재사용하지 않으며 페이지 이동은 같은 관계 집계 캐시를 사용한다. 기존 챔피언·포지션 집계 키와 history 의존성은 유지해 이름 변경으로 불필요하게 재계산하지 않는다. 운영 캐시 활성 상태는 변경하지 않는다.
- 화면 컴포넌트에서 최다 팀원, 최다 상대, 같은 팀 최고 승률, 상대 팀 최고 승률 순서로 렌더링한다. 승률 블록은 반올림 전 승률이 50%를 초과할 때만 표시하며 횟수 블록에는 이 조건을 적용하지 않는다. SQL과 캐시 결과는 유지한다. 없는 항목과 필터로 숨겨진 항목은 생성하지 않고 모두 숨겨지면 설명을 포함한 영역도 생략한다. 이름 링크의 prefetch는 끈다. CSS grid의 column 자동 배치로 한 행을 유지하고 좁은 화면에서 영역 내부 가로 스크롤을 제공한다. 남은 블록들은 사용 가능한 너비를 나눈다.

## Risks / Trade-offs

- 개인 전적에 비례하는 집계 비용 → 기존 인덱스와 독립 집계 캐시를 사용하며 raw JSON은 읽지 않는다. 추가 조회는 캐시 miss당 SQL 한 개다.
- 승패 미정이 섞인 작은 표본 → 경기 수와 승/패/미정을 표시하고 집계 기준을 설명한다.
- 로컬 성능이 운영 응답 시간을 보장하지 않음 → 로컬 회귀와 운영 미검증 범위를 별도로 기록한다.

## Migration Plan

마이그레이션 없이 배포하며 새 관계 집계 캐시 키가 기존 캐시와 공존한다. 코드 롤백은 새 키를 사용하지 않는다.
