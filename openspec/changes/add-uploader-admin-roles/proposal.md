## Why

현재 공유 키로 로그인한 모든 사람이 모임원 명부, 계정 연결과 경기 관리 정보를 변경할 수 있다. 리플레이를 제공하는 모임원에게 업로드와 조회를 허용하면서, 명부와 기록의 관리 권한은 운영자에게 제한한다.

## What Changes

- 기존 `UPLOAD_PASSWORD`를 업로더 키로 유지하고 별도의 `ADMIN_PASSWORD`를 추가한다. 같은 로그인 화면에서 입력한 키에 따라 역할을 서버가 결정한다.
- 업로더와 관리자는 리플레이 업로드·처리, 경기·통계·등록된 모임원 조회를 사용할 수 있다.
- 모임원 추가·수정, 라이엇 계정 연결·해제, 경기 날짜 수정·원본 복원 및 경기 제외·복구는 관리자에게만 허용한다.
- 관리 화면과 모든 변경 Server Action에서 관리자 역할을 검사하고, 업로더 화면에서는 관리 메뉴와 변경 폼을 표시하지 않는다.
- **BREAKING**: 역할이 서명된 새 세션 형식을 도입하고 기존 역할 없는 세션은 거부한다. 배포 후 모든 사용자는 다시 로그인해야 한다.
- **BREAKING**: `ADMIN_PASSWORD`와 독립적인 서버 전용 `AUTH_SECRET`이 필수가 된다. 키 중복·누락과 부적절한 서명 비밀값은 거부한다. 로그인 키로 세션을 서명하는 fallback을 제거한다.
- 업로더 키 교체는 업로더 세션, 관리자 키 교체는 관리자 세션, `AUTH_SECRET` 교체는 모든 세션을 무효화한다. 기존 로그인 제한과 업로드 예산·바인딩 검증을 유지한다.
- 역할별 회귀 검증과 설정·운영 문서를 추가한다.

## Capabilities

### New Capabilities

- `role-based-access`: 두 공유 키의 인증, 역할이 서명된 세션, 역할별 인가, 화면 표시, 키 교체와 기존 세션 전환 규칙.

### Modified Capabilities

없음. `openspec/specs/`에 확정된 기본 스펙이 없으므로 새 capability로 작성한다. 진행 중인 변경의 기존 공유 인증 요구사항은 이 변경이 도입하는 역할 정책에 종속된다.

## Impact

- `src/lib/auth.ts`, `session.ts`, `login.ts`, 로그인 Server Action과 Proxy의 인증·인가 흐름.
- 관리 페이지·모임원 변경 Action, 경기 관리 Action·페이지, 공통 내비게이션과 로그인 안내.
- `.env.example`, README, 개발·배포·구조 문서와 인증·인가 회귀 테스트.
- DB 스키마나 라이브러리 의존성 추가는 없다. Blob 처리와 유지보수용 `CRON_SECRET` 인증은 기존 정책을 유지한다.
- 개인별 계정, 사용자별 키 발급·취소, 개인별 업로드 소유권이나 감사 이력은 범위에 포함하지 않는다. 이 작업은 로컬 구현과 검증이며 운영 환경변수 변경·배포는 별도 작업이다.
