## Why

리그 오브 레전드 소모임에서 내전(커스텀 게임)을 자주 하지만 전적이 어디에도 남지 않아 누가 얼마나 이겼는지, 챔피언별 성적이 어떤지 추적할 수 없다. Riot의 공식 전적 서비스는 커스텀 게임 데이터를 제공하지 않으므로, 게임 종료 후 생성되는 리플레이(.rofl) 파일에서 직접 전적을 추출해 모아 두는 자체 서비스가 필요하다. 이 변경은 그 첫걸음(MVP)으로, 리플레이를 업로드하면 게임/플레이어 전적을 DB에 영구 저장하는 파이프라인을 만든다.

## What Changes

- Next.js(App Router) + TypeScript 프로젝트를 신규 생성하고 Vercel + Vercel Postgres로 배포할 수 있도록 기본 구성한다.
- 공유 비밀번호 1개로 보호되는 리플레이 업로드 화면을 추가한다. 큰 파일(.rofl 10~30MB)은 Vercel의 4.5MB 함수 본문 제한을 피하기 위해 **Vercel Blob로 클라이언트가 직접 업로드**한다.
- 업로드된 .rofl 파일의 메타데이터(statsJson)를 **로컬에서 파싱**해 게임 정보와 참가자별 전적(챔피언, KDA, 골드, 승패, 팀, 라이엇 아이디)을 추출한다. Riot API는 사용하지 않는다.
- 추출한 데이터를 Postgres에 저장한다. 동일 리플레이의 중복 저장은 파일 해시로 방지한다.
- 모임원 정보를 관리하는 데이터 모델을 추가한다: 모임원(UUID·이름·생년), 라이엇 계정(라이엇 아이디 ↔ 모임원 매핑, 한 사람이 여러 계정 가능).
- 라이엇 계정은 PUUID를 우선 식별하고 PUUID가 없을 때만 명확한 Riot ID 후보를 재사용한다. 새 계정은 미연결 상태로 저장해 관리 화면에서 수동 연결한다. 이미 연결된 구버전 계정은 이름 일치만으로 새 PUUID에 승격하지 않는다.
- 저장된 게임 목록과 게임 상세(참가자 전적)를 확인하는 간단한 조회 화면을 추가한다.

## Capabilities

### New Capabilities
- `replay-upload`: 공유 비밀번호 인증, Vercel Blob 클라이언트 직접 업로드, 파일 해시 기반 중복 방지, 파싱 파이프라인 트리거.
- `replay-parsing`: .rofl 바이너리에서 메타데이터/ statsJson을 추출해 게임·참가자 단위의 정규화된 전적 데이터로 변환(에러/지원 불가 형식 처리 포함).
- `match-storage`: 게임과 참가자 전적을 Postgres에 영속화하고 목록/상세로 조회하는 데이터 모델 및 동작.
- `member-registry`: 모임원(UUID·이름·생년)과 라이엇 계정을 관리하고, 자동/수동 연결 규칙으로 라이엇 아이디를 모임원에 매핑.

## Impact

- **신규 코드베이스**: Next.js 앱(라우트, 업로드 UI, 조회 UI, API/서버 액션), .rofl 파서 모듈, Drizzle 스키마/마이그레이션.
- **의존성**: `next`, `drizzle-orm`, `drizzle-kit`, `@vercel/postgres`, `@vercel/blob`, 비밀번호 검증용 환경변수.
- **인프라**: Vercel 프로젝트, Vercel Postgres 데이터베이스, Vercel Blob 스토어, 환경변수(`UPLOAD_PASSWORD`, `POSTGRES_*`, `BLOB_READ_WRITE_TOKEN`).
- **보안/프라이버시**: 모임원 실명·생년을 저장하므로 접근은 공유 비밀번호로 제한. 라이엇 아이디는 공개 닉네임이라 민감도 낮음.
- **제약**: Vercel 함수 본문 4.5MB 제한 → 업로드는 반드시 Blob 직접 업로드 경로 사용. 파싱은 Blob에서 파일을 받아 함수 메모리/시간 한도 내에서 수행.
