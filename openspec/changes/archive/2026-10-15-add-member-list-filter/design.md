## Context

`/members`는 서버에서 `getMembersReadModel()`로 권한이 반영된 전체 모임원과 연결 계정을 불러와 카드를 표시한다. 기존 메인 검색은 서버의 정확 일치·자동완성을 사용하므로 이번 부분 일치 필터와 동작이 다르다. 설치된 Next.js의 Server/Client Components 및 `use client` 문서를 기준으로 경계를 구성한다.

## Goals / Non-Goals

**Goals:**

- 제목과 같은 줄의 검색 입력으로 이름과 모든 연결 계정의 라이엇 ID를 즉시 필터링한다.
- 검색 중 네트워크 요청 없이 현재 페이지의 카드 목록과 빈 결과 안내를 갱신한다.
- 기존 모임원 순서, 전체 계정 표시, 권한별 생년 표시와 관리 기능을 유지한다.

**Non-Goals:**

- 메인 검색·자동완성, 관리자 목록, DB/캐시/API 계약 변경.
- 검색어 URL 저장, 검색 결과 페이지 이동, 별도 검색 인덱스나 의존성 추가.

## Decisions

- 서버 페이지는 인증 및 기존 read model 호출을 유지하고 직렬화 가능한 투영 결과만 작은 클라이언트 목록 컴포넌트에 전달한다. 전체 페이지를 클라이언트로 전환하거나 검색 API를 재사용하지 않는다.
- 검색어와 이름/표시 라이엇 ID를 NFC 정규화·양끝 공백 제거·소문자 변환한 뒤 `includes`로 비교한다. 한 계정이라도 맞으면 모임원 카드 전체를 한 번 표시하며, 계정이 없는 모임원도 이름으로 검색된다. `%`, `_`, `#`는 모두 일반 문자다.
- 검색어는 React state 하나로 보관하고 결과는 입력마다 기존 목록에서 계산한다. URL, effect, debounce, 서버 액션 및 fetch는 필요하지 않다. 모임원 상세/관리 링크는 prefetch를 끄고 클릭 시 이동해 결과 표시 때문에 요청이 생기지 않게 한다.
- 헤더 전용 grid로 제목·검색 입력·관리 버튼을 배치하고 설명은 아래 행에 둔다. 좁은 화면에서도 제목과 입력을 같은 줄에 유지하며 관리 버튼은 별도 행으로 내려 가로 넘침을 방지한다.
- 입력에 접근 가능한 이름을 제공하고 결과 수를 상태 영역으로 알린다. 등록 목록이 비면 기존 안내를, 검색 결과만 비면 별도의 검색 결과 없음 안내를 표시한다.

## Risks / Trade-offs

- [큰 목록의 입력별 선형 탐색] → 현재 전체 목록 규모에 맞는 단순 필터를 사용하며 추가 서버 호출 없이 처리한다.
- [열린 화면의 데이터는 초기 조회 시점 기준] → 기존 데이터 로딩 수명과 동일하며 새로고침 시 최신 데이터를 가져온다.
- [클라이언트 경계로 전달되는 개인정보] → 기존 역할별 read model 투영을 그대로 사용하고 viewer 생년 누락을 회귀 검사한다.
- [브라우저 배치와 이벤트 검증] → 실제 컴포넌트와 CSS의 합성 데이터 미리보기로 확인하고 운영 인증 화면 검증과 구분해 기록한다.
