## Context

현재 `NicknameSearchForm`은 200ms 지연 후 `/api/search/autocomplete?nickname=...`를 호출하고 Riot ID 후보를 선택하면 `/search?nickname=...`로 이동한다. 서버는 PostgreSQL에서 현재 연결과 활성 경기 조건을 다시 확인해 모임원 전적으로 보낸다.

`nickname-autocomplete.ts`는 계정 ID·닉네임·태그만 담은 Valkey Sorted Set/Hash 인덱스를 사용한다. 인덱스는 60초 TTL, 커밋 후 캐시 세대 교체, 원자 게시, 중복 재구축 병합, DB 대체 조회를 제공한다. `resolveNicknameMember`는 여러 계정 행 중 처음 20개를 잘라 선택지를 만들기 때문에 다계정 모임원이 다른 모임원의 결과를 가릴 수 있다.

현재 일반 사용자도 모임원 이름 원문을 볼 수 있고 생년은 서버 투영에서 제거된다. 모임원 상세는 계정이나 경기가 없어도 빈 전적을 표시하며, 로그인 계정과 게임 모임원은 독립되어 있다.

## Goals / Non-Goals

**Goals:**

- 메인 검색창에서 이름과 Riot ID를 입력하고 자동완성 후보를 선택해 전적으로 이동한다.
- 동명이인과 이름·닉네임 충돌을 사용자가 구분하게 하고, 동일 모임원의 여러 계정을 결과에서 합친다.
- 기존 닉네임 검색 URL, 키보드·한글 조합 입력, JavaScript 없는 GET 제출을 유지한다.
- 생년 숨김, 요청별 인가, 현재 DB 기준의 이동과 캐시 무효화를 유지한다.

**Non-Goals:**

- 초성 검색, 오타 보정, 포함 문자열 자동완성, 외부 Riot API 검색.
- Discord 로그인 계정 이름 검색, 로그인 계정과 모임원 연결, 새로운 개인정보 공개.
- DB 스키마 변경, 새로운 검색 서비스 도입, 검색 기록 수집.

## Decisions

### 1. 이름은 등록된 모임원 전체를 대상으로 한다

`members`에 존재하는 모든 모임원을 이름 검색 대상으로 한다. 연결 계정이 없거나 전적이 없는 사람도 선택해 기존 빈 전적 화면으로 이동할 수 있다. Riot ID 검색은 지금처럼 모임원에 연결되고 활성 경기 기록이 있는 계정만 대상으로 한다.

이름 검색까지 활성 경기 조건으로 제한하는 대안은 방금 등록한 모임원이 검색되지 않는 문제가 있어 채택하지 않는다. 동명이인 후보는 연결된 Riot ID를 최대 2개 보여주고 계정이 없으면 `연결된 계정 없음`을 표시한다. 이름과 연결 계정 표시가 모두 같아도 후보를 합치거나 생년을 노출하지 않으며 ID가 다른 모임원을 임의로 선택하지 않는다.

### 2. 새 통합 입력은 q를 사용하고 기존 nickname 요청은 호환한다

- 메인 폼은 `GET /search?q=...`, 자동완성은 `GET /api/search/autocomplete?q=...`를 사용한다.
- `q`는 이름과 Riot ID를 함께 검색한다. 이름은 NFC·양끝 공백·대소문자를 정규화하고 접두어로 추천한다. 직접 제출은 전체 이름의 정확 일치이다.
- Riot ID는 기존 닉네임 접두어 및 `닉네임#태그접두어` 자동완성과 정확 닉네임/태그 제출 규칙을 유지한다. `q`의 이름 분기는 `#`를 일반 이름 문자로 취급하고, Riot ID 분기만 태그 구분자로 해석한다.
- 공백만 있는 입력, 100 Unicode code point 초과, 제어 문자 또는 잘못된 UTF-16은 검색하지 않는다. 빈/잘못된 검색어의 자동완성은 빈 목록, 제출은 기존 없는 사용자 안내로 처리한다. 반복 파라미터 또는 `q`와 `nickname` 동시 전달은 API에서 400, 페이지에서는 없는 사용자 안내로 처리한다.
- 기존 `nickname` 전용 URL은 Riot ID 검색으로 유지한다. 특히 기존 자동완성 응답 `{ suggestions: [{ id, gameName, tagLine }] }`는 바꾸지 않아 열려 있던 이전 클라이언트도 사용할 수 있다.
- UI 문구는 `모임원 이름 또는 롤 닉네임#태그를 입력하세요`, 접근성 이름은 `모임원 이름 또는 롤 닉네임 검색`으로 맞춘다. 결과 제목과 오류·없는 사용자 안내도 두 종류의 입력을 설명한다.

기존 `nickname`의 의미와 응답을 한 번에 바꾸는 대안은 저장된 URL과 기존 클라이언트의 기대를 깨뜨리므로 새 `q` 계약으로 분리한다.

### 3. 자동완성은 명시적인 두 후보 유형을 반환한다

새 `q` 응답의 `suggestions`는 다음 최소 형태를 갖는다. 서버와 클라이언트 모두 허용한 속성만 투영한다.

| kind           | 속성                                                                   | 표시와 이동                                                                    |
| -------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `member`       | `id`(모임원 UUID), `name`, `accounts`(최대 2개의 `gameName`·`tagLine`) | 이름 + `모임원` 표시 + 연결된 Riot ID. `/members/{id}`로 이동                  |
| `riot-account` | `id`(계정 UUID), `gameName`, `tagLine`                                 | Riot ID + `라이엇 계정` 표시. 기존 `/search?nickname=...`에서 현재 연결을 확인 |

반환 수는 합계 10개이며 `(kind, id)`로 중복을 제거한다. 두 종류에 우선 5개씩 배정하고 한쪽이 부족하면 나머지 자리를 다른 쪽에 준다. 화면은 모임원 후보 다음 Riot ID 후보 순서이고, 각 종류는 정규화한 이름/Riot ID의 UTF-8 바이트 순서와 UUID로 안정적으로 정렬한다. 후보 상한 밖의 동명이인은 이름 전체를 제출해 페이지가 있는 결과에서 확인할 수 있다.

같은 모임원의 이름 후보와 Riot ID 후보는 유형이 다르므로 자동완성에서는 함께 나타날 수 있다. 모임원별 중복 제거는 최종 제출 결과에서 적용한다. 반환된 임의 URL을 사용하는 대신 검증한 종류·UUID·Riot ID로 내부 경로를 만든다.

### 4. 최종 제출은 전체 정확 일치 결과를 모임원별로 합친다

`/search?q=...`는 인증 후 현재 PostgreSQL의 정확 이름 일치 모임원과 정확 Riot ID 일치 계정의 연결 모임원을 합친다. 같은 모임원이 두 분기나 여러 계정에 걸려도 한 건이다. 이름과 닉네임이 다른 사람을 가리키면 한쪽을 우선하지 않고 모두 선택지로 표시한다.

- 0명: 기존 `/search/not-found`.
- 1명: `/members/{id}`로 이동.
- 2명 이상: 이름과 연결 Riot ID를 표시하는 선택 목록. 모임원 ID 기준 중복 제거 후 20명 단위로 페이지를 나누며 `q` 또는 `nickname`과 `page`를 링크에 유지한다.

현재의 계정 행 `slice(0, 20)` 후 선택 방식은 모임원별 그룹화·전체 건수 판정·페이지 절단 순서로 바꾼다. `nickname` 전용 제출도 이 결과 모델을 사용하되 이름 분기는 수행하지 않는다. DB 조회 오류는 없는 사용자로 바꾸지 않는다.

이름 후보에서 직접 이동한 상세 페이지는 현재 세션과 모임원 존재를 다시 확인한다. 추천 후 삭제된 모임원은 기존 404로 처리한다. 이름이 변경된 경우 같은 UUID의 최신 정보가 표시된다. Riot ID 후보는 캐시의 모임원 연결을 믿지 않고 기존처럼 제출 시점의 연결을 판정한다.

### 5. 이름 인덱스를 분리하고 기존 캐시 세대를 공유한다

기존 `autocomplete:v1` Riot 계정 인덱스는 유지한다. 이름 인덱스는 별도의 `member-autocomplete:v1` 공간에 `정규화한 이름 + 구분자 + 모임원 UUID` 키와 위의 최소 표시 정보를 저장한다. 두 인덱스 모두 현재 캐시 세대에 속하며 60초 TTL을 사용한다.

공통화가 필요하면 Sorted Set/Hash의 게시·조회·단일 재구축 로직만 내부 helper로 추출하고, 후보 검증·최소 투영·대상 조회는 유형별로 유지한다. 이름은 모든 로그인 역할에 공개되므로 이름 인덱스는 역할 공용이지만 접근 전 DB 세션 검증은 매번 수행한다. 생년·Discord 계정 정보·자격 증명은 인덱스와 응답에 넣지 않는다.

모임원 추가·이름 수정·삭제, 계정 연결·해제·닉네임 변경, 경기 수집·제외·복구는 기존 `withActorTransaction`의 커밋 후 세대 갱신으로 양쪽 인덱스를 무효화한다. 실패·롤백은 새 세대를 발행하지 않는다. 초기 인덱스 구축은 필요한 컬럼만 조회하고 계정 미리보기는 일괄 조회·그룹화해 모임원별 N+1 쿼리를 만들지 않는다. 오래된 재구축은 캡처한 세대에만 게시한다.

Valkey가 없거나 장애가 나면 동일 정규화·정렬·개수 제한을 적용한 DB 결과를 사용한다. 두 소스 중 하나의 DB 조회가 실패하면 불완전한 성공 목록을 반환하지 않고 일시 오류를 반환하며 직접 GET 제출은 계속 제공한다. 인덱스/브라우저 응답은 분리하고 API의 `private, no-store`를 유지한다.

### 6. 기존 입력 상호작용을 유지한다

200ms debounce, 요청 취소, 오래된 응답 무시, 방향키·Enter·Escape, blur와 포인터 선택을 유지한다. 한글 IME 조합 중 Enter는 선택/제출로 처리하지 않는다. 자동완성 실패 시 `자동완성을 불러오지 못했습니다. 이름이나 닉네임을 직접 입력해 검색하세요.`로 안내한다. 클라이언트는 응답의 종류·UUID·문자열·미리보기 배열과 크기를 검증하고, 이름·Riot ID는 React 텍스트로 렌더링한다.

## Risks / Trade-offs

- [모임원 이름 인덱스에 개인정보 범위 확대] → 현재 모든 로그인 사용자에게 공개된 이름과 이미 조회 가능한 연결 Riot ID만 저장하고 생년·로그인 계정 정보는 제외한다.
- [추천은 수정 직후 잠시 오래될 수 있음] → 세대 무효화와 60초 TTL을 적용하고 상세/최종 제출에서는 현재 DB를 확인한다.
- [동명이인·다계정의 결과 누락] → 모임원 기준으로 합친 뒤 페이지를 나누고, 20개를 넘는 계정이 있는 모임원과 다른 모임원이 함께 일치하는 회귀를 둔다.
- [연결 계정 없는 동명이인은 표시 정보가 같을 수 있음] → 별도 후보를 유지하며 임의 이동·생년 공개를 하지 않는다. 추가 식별 라벨 도입은 별도 요구사항으로 다룬다.
- [전체 이름 인덱스 최초 구축 비용] → 기존 소규모 모임 서비스의 60초 인덱스 구조를 재사용하고 N+1을 피한다. 대규모 검색 전용 DB/서비스는 별도 설계한다.

## Migration Plan

1. 관련 Next.js 로컬 가이드를 확인한 뒤 명세 순서대로 서버·클라이언트·캐시·테스트를 구현한다.
2. 새 이름 인덱스는 첫 요청에서 생성한다. DB migration이나 운영 캐시 전체 삭제는 필요하지 않다.
3. 역할별 API/HTML, 실제 로컬 Valkey, 브라우저 입력·선택과 기존 `nickname` URL 호환을 검증한다. 전체 `npm run check`와 strict OpenSpec 검증을 수행한다.
4. 향후 배포 시 `q` 요청의 오류와 이름·Riot ID 이동을 확인한다. 롤백은 이전 앱 버전으로 돌아가며 새 이름 인덱스는 TTL로 정리된다. 롤백된 이전 앱은 새 `q` 링크를 처리하지 못할 수 있지만 기존 `nickname` 링크는 유지된다.

## Open Questions

구현을 막는 미결정 사항은 없다. 이름 검색 범위는 전체 등록 모임원, 검색 방식은 접두어 추천·정확 일치 제출로 계획한다. 계정이나 경기가 없는 사람도 검색된다는 점은 이 계획의 기본 UX 결정이다.
