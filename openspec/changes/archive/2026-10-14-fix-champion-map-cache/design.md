## Context

`champions.ts`는 두 DataDragon 응답을 검증해 표시명 맵을 만들고, 두 요청과 본문 처리를 합쳐 2초 안에 끝낸다. 성공한 모듈 전역 `memo`는 현재 만료되지 않으며 진행 중인 조회도 공유하지 않는다.

## Goals / Non-Goals

**Goals:** 메모리 재사용 시간을 24시간으로 제한하고 같은 인스턴스의 동시 최초 조회·갱신을 합친다. 기존 검증, 타임아웃과 실패 후 재시도 동작을 유지한다.

**Non-Goals:** Redis 공유 저장, 정적 JSON 배포, Next.js 태그 캐시 전환, DB 검색 인덱스 추가와 외부 데이터의 24시간 이내 최신성 보장.

## Decisions

- 메모리는 `{ map, expiresAt }`으로 보관한다. 성공한 비어 있지 않은 맵을 받은 시점부터 24시간 후 만료하며, 경계 시각을 포함해 만료된 맵은 사용하지 않는다. 접근마다 수명을 연장하지 않는다.
- 만료 확인과 진행 중인 Promise 선택을 담당하는 함수와 기존 2초 조회 함수를 분리한다. 공유 Promise의 `finally`에서 참조를 지워 성공·오류·빈 응답·타임아웃 이후 재시도를 허용한다.
- 타임아웃 이후 늦은 응답은 메모리나 새 조회의 Promise에 영향을 줄 수 없다. 저장은 기존 `Promise.race`의 성공 경로 안에서만 수행한다.
- 만료 후 조회 실패도 내부 이름으로 폴백한다. 이전 맵을 무기한 제공하거나 실패를 하루 동안 캐시하지 않는다. 이는 기존 실패 복구 계약을 유지한다.
- Next.js fetch의 하루 재검증은 유지한다. 이 변경은 프로세스 메모리의 재사용 기간을 제한하며, 프레임워크 캐시의 응답이 원본 서버와 항상 최신이라고 가정하지 않는다.

## Risks / Trade-offs

- 만료 직후 호출은 갱신을 기다린다 → 기존 전체 2초 제한을 유지하고 동시 호출은 같은 제한을 공유한다.
- 프로세스 간에는 조회가 합쳐지지 않는다 → 기존 Next.js fetch 캐시를 유지하며 배포 환경의 실제 외부 호출 수는 별도 검증 대상으로 둔다.
- 장애 중 순차 호출은 다시 시도한다 → 실패 응답을 장기 캐시하지 않는 기존 복구 동작을 유지한다.

## Migration Plan

DB·환경변수 변경 없이 애플리케이션 코드를 배포한다. 롤백은 이전 애플리케이션 커밋으로 가능하다. 기존 MVP 설계의 메모리 무기한 유지 설명은 당시 구현 이력이며 이 변경이 현재 계약을 정의한다.
