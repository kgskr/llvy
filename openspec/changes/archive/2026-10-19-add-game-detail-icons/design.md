## Context

상세 화면은 챔피언 문자열과 K/D/A·골드를 표시한다. 파서는 `raw_stats`에 `ITEM0`~`ITEM6`을 보존하지만 상세 조회는 이를 노출하지 않는다. 기존 모임원 이름 조회의 24시간 캐시와 2초 제한은 유지한다.

## Goals / Non-Goals

**Goals:** 챔피언 이름 옆 초상화, 별도 아이템 컬럼, 슬롯 순서·장신구 구분, 접근성 및 실패 폴백을 제공한다.

**Non-Goals:** 다른 상세 통계, 구매 순서, 툴팁의 아이템 능력치, DB 스키마 변경, 목록·모임원 화면 확장.

## Decisions

- 조회 단계에서 일곱 슬롯을 `number | null`로 정규화한다. 0은 빈 슬롯, null은 누락/잘못된 값이다. 원본 JSON은 read model과 클라이언트에 전달하지 않는다. 상세 캐시 키의 버전을 올려 이전 응답과 구분한다.
- 상세 전용 DataDragon 조회는 기록된 게임의 major/minor 패치에 해당하는 공식 버전을 선택한다. 버전이 없을 때만 최신 버전을 선택하고, 기록된 패치를 찾지 못하면 자산을 추측하지 않는다. 한국어 챔피언·아이템 카탈로그는 병렬 조회한다.
- 조회 전체를 2초로 제한한다. 성공한 카탈로그만 완료 시점부터 24시간, 최대 8개 패치까지 메모리에 보관하고 진행 중 조회를 공유한다. 실패는 다음 요청에서 재시도하고 늦은 결과는 캐시에 반영하지 않는다. Next fetch revalidation도 24시간이다.
- 고정 Riot CDN 주소와 검증된 이미지 파일명만 사용한다. 챔피언 내부명은 소문자로 비교하되 원본 표시명 폴백을 유지한다. 아이템은 해당 패치 카탈로그에서 이름과 이미지 파일명을 찾는다.
- 작은 Client Component가 `next/image`의 오류를 처리한다. 이미지 크기를 예약하고 실패한 이미지를 자리표시자로 대체한다. 작은 CDN PNG는 `unoptimized`로 직접 표시한다. 아이템 이름은 title/접근성 이름에 제공한다.
- 32px 아이콘, 6칸 + 간격 + 장신구 한 칸을 사용한다. 좁은 화면에서는 기존 표 내부 스크롤을 유지한다.

## Risks / Trade-offs

- 카탈로그/이미지 장애 → 챔피언 원문과 아이템 자리표시자로 경기 정보를 계속 제공한다.
- 과거 패치/알 수 없는 아이템 → ID 기반 접근성 설명을 유지하며 다른 아이템으로 추측하지 않는다.
- 원본 통계 누락 → 빈 슬롯과 구별하는 미확인 표시를 제공한다.
- DataDragon 패치와 클라이언트 빌드 번호는 다름 → major/minor가 일치하는 공식 버전 목록의 첫 항목을 사용한다.

## Migration Plan

마이그레이션 없음. 기존 원본 통계에 아이템이 있으면 재업로드 없이 표시한다. 롤백은 코드 되돌리기만 필요하다.
