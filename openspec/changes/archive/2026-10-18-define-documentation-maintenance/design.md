## Context

LLVY는 본체 문서와 API 계약을 소유하고, Worker·업로더는 각자의 구현과 운영 문서를 소유한다. 위키는 부가 서비스의 맥락과 원본 링크를 제공한다. 현재 지침은 원본 확인과 검증을 요구하지만 변경 유형별 갱신 위치, 색인 이동과 문서 완료 조건은 분산되어 있다.

## Goals / Non-Goals

**Goals:** API·설정·명령·구조·문서 생명주기의 갱신 대상, 공개 문서 작성 기준, 확인일·검증·후속 작업의 구분을 실행 가능한 지침으로 제공한다.

**Non-Goals:** 기능 구현, 자동 문서 생성·동기화, CI 추가, 공개 계약·개인정보 처리 정책 변경, 기존 기능 change 완료 처리.

## Decisions

- LLVY는 `docs/documentation.md`에 본체 갱신 표를 두고 AGENTS와 문서 색인에서 연결한다. Worker와 업로더는 각각 AGENTS에 자체 갱신 표를 둔다. 위키만 단일 필수 지침으로 쓰면 독립 체크아웃에서 참조할 수 없으므로 로컬 규칙을 유지한다.
- 위키의 `wiki/documentation.md`는 서비스 간 요약·색인·링크·출처·변경 기록의 갱신과 완료 검사를 설명한다. AGENTS·README·llms.txt에서 연결하고 주제 템플릿에도 근거와 상태 구분을 반영한다.
- 원본을 먼저 수정하고 영향을 받는 요약만 갱신한다. LLVY 내부 변경을 위키에 모두 복제하지 않는다. 관련 저장소가 없으면 로컬 작업을 마치고 연계 문서의 저장소·경로·수정 내용을 남기며 동기화 완료로 보고하지 않는다.
- 공개 문서에는 기술 사실·결정 이유·재현 가능한 검증 범위를 쓴다. 개인 경로·개인 도구 정책·전역 지침·대화 경위·에이전트 권한 승인 과정은 넣지 않는다. 공통 개발 요건과 검증에 필요한 런타임 버전은 유지한다.
- 문장 수정만으로 사실 확인일을 올리지 않는다. 과거 검증 기록과 현재 안내를 구분하고 파일 이동·제목 변경 후 인바운드 링크와 앵커를 확인한다. 문서 규칙은 수동 편집 절차이며 자동 검사로 오해시키지 않는다.

## Risks / Trade-offs

- [저장소별 지침 중복] → 원본 소유권을 명시하고 각 로컬 표에는 해당 저장소의 최소 규칙만 둔다.
- [계획이 구현 사실로 바뀜] → 계획·코드·외부 검증 상태를 별도로 확인하고 미구현 문구의 제거 조건을 둔다.
- [불필요한 확인일 갱신] → 외부 근거를 재확인하지 않은 문구 수정은 확인일을 유지한다.

## Migration Plan

지침과 색인을 함께 갱신한 뒤 API·설정·명령·문서 이동 사례로 갱신 대상을 추적한다. 링크·형식·strict 검증과 기존 기능 작업 상태를 확인하고 문서 관리 change만 아카이브한다. 런타임 배포와 데이터 마이그레이션은 없다.
