> 이 디렉터리는 완료된 변경의 당시 설계·구현 기록이다. 현재 요구사항은 [주 명세](../../../specs)를 따른다. 여기에 남은 제공자·리전·인증 전환 설명은 신규 배포 지침이 아니다.

## Why

Redis 장애가 나면 선택적인 캐시가 요청을 1초 막는다. 자동완성 핸들러와 DAL, 페이지와 레이아웃에서 동일 요청의 인증 DB 조회가 반복되어 정상 응답에도 왕복 지연이 추가된다.

## What Changes

- Redis 연결·준비·명령 실패 제한을 100ms로 줄여 빠르게 DB로 대체한다. 실패한 연결 공유와 5초 재시도 간격은 유지한다.
- 페이지 렌더링과 명시적인 읽기 API 요청 범위에서만 인증 결과와 진행 중 Promise를 공유한다.
- 다음 요청은 DB 인증을 다시 수행하고, 변경 작업·업로드 직전 재검증은 항상 새로 조회한다.
- 실제 Redis 응답 중단 및 인증 조회 횟수·요청 격리·권한 회수 회귀를 추가한다.

## Capabilities

### New Capabilities

- `bounded-cache-and-request-auth`: 빠른 선택 캐시 장애 처리와 요청 안의 읽기 인증 중복 제거.

### Modified Capabilities

없음. 기존 변경 문서의 1초 캐시 제한은 이 변경으로 대체한다.

## Impact

Redis 연결, 읽기 인증 도우미, 자동완성 API, 페이지·읽기 모델, 회귀 테스트와 운영 문서를 변경한다. DB 스키마·인증 권한·응답 DTO·의존성은 바꾸지 않는다.
