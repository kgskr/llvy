# 서버 계획의 리뷰 이력

이 변경은 2026-10-16에 검토한 혼합 계획의 서버 부분을 2026-10-18에 분리했다.
[과거 리뷰 원본](../../../../llvy-uploader/docs/history/2026-10-18-monorepo-plan/review.md)과
[작업 이동표](../../../../llvy-uploader/docs/repository-split.md)를 함께 읽는다.
원본의 경로·작업 수·검증 결과는 당시 상태다. 이번 분리는 새 보안 리뷰나 기능 구현 검증이 아니다.
현재 인증·API·기존 웹 델타는 이 change의 `specs/`, 앱 명세는 업로더 저장소가 소유한다.

## 2026-10-18 저장소 분리 후 계획 리뷰 수정

서버 계획·업로더 계획·저장소 역할을 나눠 수행한 서브에이전트 리뷰에서 서버 계획의 P3 명세 누락 1건을 확인했다. 기존 `blob-processing-ownership`은 `/api/uploads`가 발급한 바인딩만 처리할 수 있다고 정의했지만 새 desktop 예약 경로에 대응하는 델타가 없었다. 소비된 바인딩의 거부 및 만료 시나리오도 데스크톱의 저장된 결과 재조회와 구분할 필요가 있었다.

[Blob 소유권 델타](specs/blob-processing-ownership/spec.md)를 추가하고 proposal·design·회귀 검증 작업에 연결했다. 웹 계약을 유지하면서 desktop 예약의 기기·경로 바인딩, 재처리 금지, 현재 권한을 검사하는 결과 재조회와 예약 만료의 경계를 명시했다. 기존 정리·공유 예산 요구는 변경하지 않는다.

이번 수정은 미구현 계획의 일관성 보완이다. [현행 정식 명세](../../specs/blob-processing-ownership/spec.md)는 변경하지 않고, 기능 작업 36개는 미완료로 유지한다. 실제 구현과 필수 검증을 마친 후에만 정식 명세를 동기화하고 아카이브한다.

수정 후 서버 담당 서브에이전트의 읽기 전용 재검토에서 기존 P3 해결을 확인했으며 추가 P1/P2/P3는 발견하지 못했다. `openspec validate --all --strict`는 29개 모두 통과했다. 변경 문서 5개의 Prettier·공백·로컬 링크 9개를 검사했고, proposal의 capability 6개와 델타 디렉터리가 일치함을 확인했다. 변경 대상 기존 요구사항 3개의 시나리오 이름과 결과를 보존하고 웹 경로를 명시했으며, 현행 정식 명세의 변경 없음도 원본 바이트와 SHA-256으로 확인했다. `git diff --check`도 통과했다. 구현·실제 DB·Blob 검증은 수행하지 않았다.
