## Context

현재 게임 목록은 25경기씩 인원수를 표시한다. 참가자의 모임원 연결·팀·챔피언·포지션은 이미 저장돼 있고 챔피언 이름·초상화 캐시는 공유할 수 있다. 사용자가 팀별 두 줄형 시안을 선택했다.

## Goals / Non-Goals

**Goals:** 페이지당 10경기, 모임원 이름 우선, 초상화와 `JUG` 약어, 승리 팀 배경, 페이지에 한정된 참가자 조회.

**Non-Goals:** 모임원 최근 경기의 이름·포지션 표기 변경, DB 마이그레이션, 신규 Riot API, 운영 배포.

## Decisions

- 기존 `listGames` DTO를 유지하고 목록 화면 전용 `listGamesWithParticipants`를 추가한다. 먼저 경기만 정렬·LIMIT/OFFSET 조회하고, 선택된 ID의 참가자·계정·모임원 이름을 한 번의 IN 쿼리로 읽는다. 전체 참가자 JOIN 후 페이지를 자르거나 경기마다 상세를 읽지 않는다. 빈 페이지는 참가자 조회를 생략한다.
- 참가자 DTO는 ID·팀·포지션·챔피언·계정 이름/태그·모임원 ID/이름만 포함한다. 생년·PUUID·원본 통계를 선택하지 않는다. 참가자 수는 반환된 배열에서 계산해 기존 요약 필드를 유지한다.
- `game-list-v2` 캐시 키로 형식을 분리하고 60초 캐시·쓰기 이후 무효화·읽기 전 인증을 유지한다. 계정 연결/해제, 모임원 이름 변경/삭제도 기존 무효화로 새 이름을 반영한다.
- 화면은 서버 컴포넌트로 렌더링하며 초상화 오류 처리만 기존 AssetIcon을 사용한다. 최신 챔피언 카탈로그의 이름/초상화 캐시를 공유하고 아이템 카탈로그를 요청하지 않는다. 상세·모임원 링크의 prefetch를 끈다.
- 블루/레드 각 팀은 TOP·JUG·MID·BOT·SUP 순서로 정렬한다. 미확인 포지션은 ‘불명’, 미확인 팀은 별도 그룹으로 보존한다. 승리 팀 미확인은 중립색을 사용한다. 좁은 화면은 메타정보와 참여자를 줄바꿈하며 긴 이름도 안전하게 표시한다.
- 제외된 경기에서도 같은 목록과 페이지 크기를 사용하고 관리자/오너의 기존 복구 폼과 피드백을 유지한다.

## Risks / Trade-offs

- 이름·연동 정보 캐시 지연 → 기존 쓰기 무효화를 회귀로 검증하고 캐시 TTL을 유지한다.
- 참가자/이미지 누락 → 참가자 없음 안내와 초상화 자리표시자로 정보를 보존한다.
- 운영 성능은 로컬로 증명할 수 없음 → 쿼리 횟수·페이지 범위와 실제 로컬 Redis 재사용을 검증한다.

## Migration Plan

스키마 변경 없이 적용한다. 이전 캐시 키와 공존하므로 코드 롤백이 가능하다.
