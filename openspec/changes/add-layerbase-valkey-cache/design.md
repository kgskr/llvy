## Context

Vercel의 Layerbase 연동이 `VALKEY_URL`을 제공한다. 앱은 Node.js 서버에서 PostgreSQL을 사용하며 읽기 모델에서 현재 세션을 확인하고 일반 사용자 이름·생년을 투영한다. 랜딩의 검색은 아직 정적 UI다.

## Goals / Non-Goals

**Goals:** 게임·모임원 조회 비용 절감, 권한별 캐시 분리, 데이터 변경 후 무효화, 장애 시 조회 지속, 닉네임 자동완성과 연결된 모임원 검색.

**Non-Goals:** 외부 Riot API 호출, 세션·관리자 자격증명·감사로그·요청 제한의 Valkey 이전, 전문 검색 모듈 설치, 초성·오타 검색.

## Decisions

1. `ioredis`가 `VALKEY_URL`로 연결한다. 운영은 `rediss://`와 인증서 검증·SNI를 사용한다. 로컬 루프백의 `redis://`만 개발·테스트에서 허용한다. REST도 지원되는 제공자지만 사용자가 이미 설정한 URL과 표준 프로토콜을 따른다. 서버 인스턴스마다 지연 연결 하나를 재사용하고 연결·명령 대기와 재시도를 제한한다.
2. 조회 모델에서 매번 세션을 먼저 검증한다. 캐시 키에 역할·조회 종류·모든 인자를 포함하고, 일반 사용자용 결과를 마스킹한 뒤 저장한다. 원문 개인정보와 역할별 결과를 공동으로 캐시하지 않는다. 관리 화면의 현재 관리자 지정 정보, 인가와 감사 조회는 직접 DB를 사용한다.
3. 결과 TTL은 60초다. 환경과 PostgreSQL DB 식별자 해시를 키 공간에 넣어 다른 DB의 결과를 공유하지 않는다. 선택적 `VALKEY_KEY_PREFIX`로 같은 DB를 쓰는 독립 앱도 구분한다. 키에는 검색어 원문을 넣지 않고 인자 해시를 사용한다.
4. 무효화는 커밋 후 공유 세대 키를 새 UUID로 바꾸는 방식이다. 읽기 시작 때의 세대로 저장하므로 무효화 전에 시작한 조회가 나중에 완료되어도 새 세대에 이전 결과를 채우지 않는다. 이전 결과는 TTL로 정리한다. 세대 키가 사라지면 새 UUID를 `SET NX`로 초기화한다.
5. 저장된 계정 검색은 NFC·대소문자·양끝 공백을 정규화하고 닉네임 부분 일치와 선택적 정확한 태그 일치를 조회한다. `%`·`_`는 문자 그대로 비교한다. 모임원에 연결되고 활성 경기 기록이 있는 계정만 최대 20개 반환하며 모임원 이름은 역할별로 투영한다. PostgreSQL은 원본 계정을 제공하고 Valkey는 검색 결과를 캐시한다. 자동완성과 제출의 Unicode 일치를 위해 양쪽 모두 JavaScript 정규화 함수를 쓴다. DB의 locale 의존적인 `lower()`를 피하는 대신 검색 제출과 캐시 miss에서 활성 연결 계정 집합을 읽는다. 대규모 계정 집합을 운영하게 되면 공통 정규화 열로 조회를 옮길 수 있다.
6. 자동완성은 점수 0인 Sorted Set에서 정규화한 `닉네임#태그` 접두어를 `ZRANGE BYLEX`로 조회한다. Hash에는 계정 ID·닉네임·태그만 저장한다. 최대 10개를 반환하고 한글·영문 대소문자·NFC·태그 접두어를 지원한다. 공통 세대와 60초 TTL을 사용해 변경 후 첫 조회 또는 만료 시 활성 경기 계정 인덱스를 다시 만든다. 임시 키에 구축한 뒤 트랜잭션으로 게시해 부분 인덱스를 노출하지 않는다. Valkey 장애 시 DB 원본으로 동일한 결과를 만든다.
7. 검색 제출은 닉네임과 선택적 태그를 정확히 일치시킨다. 이동할 모임원 연결은 매번 DB에서 확인한다. 한 모임원으로 일치하면 `/members/{id}`, 여러 모임원이면 선택 목록(최대 20개), 일치하는 연결이 없으면 `/search/not-found`로 이동한다. 태그 없이도 같은 모임원의 여러 계정은 단일 모임원으로 처리한다. 제외 경기만 있는 계정과 미연결 계정은 검색 이동 대상에서 제외한다.
8. 랜딩은 GET 검색 폼으로 JavaScript 없이도 제출된다. 입력 중 200ms 지연 후 인증된 자동완성 API를 호출하고 이전 요청을 취소한다. 키보드 방향키·Enter·Escape와 마우스 선택을 제공하며 오래된 응답이 현재 입력을 덮지 못하게 한다. API 응답과 검색 페이지는 공유 HTTP 캐시를 금지한다. 일반 사용자 개인정보 마스킹은 모임원 상세와 선택 목록 모두 기존 투영을 따른다.

## Risks / Trade-offs

- 캐시 장애나 누락 → 직접 DB 조회, 쓰기 커밋은 캐시 실패로 실패 처리하지 않는다. 무효화 실패 시 기존 항목은 60초 TTL로 만료한다. 분산 DB/캐시 원자성을 요구하는 outbox는 현재 소규모 범위에서 제외한다.
- 휴면 서버 또는 연결 한도 → 연결 재사용, 연결·명령 제한 시간, 오류 후 짧은 재시도 유예. 첫 요청은 직접 DB로 처리될 수 있다.
- 캐시 내용 불일치 → 스키마 버전을 키와 값에 포함하고 손상된 JSON은 miss로 처리한다. 큰 결과는 캐시하지 않는다.

## Migration Plan

DB 마이그레이션은 없다. Vercel에서 환경별 `VALKEY_URL`과 PostgreSQL 대상을 확인한 뒤 배포한다. 두 번 조회, 데이터 변경 후 새 결과, 권한별 개인정보, 장애 시 DB fallback을 Preview에서 확인한다. URL을 제거하고 재배포하면 캐시 없이 기존 DB 경로로 동작한다.
