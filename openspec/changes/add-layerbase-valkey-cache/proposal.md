## Why

게임·모임원 조회와 전적 집계를 매번 PostgreSQL에서 실행하고 있다. Layerbase Valkey를 조회 캐시와 닉네임 자동완성 인덱스로 연결하고, 닉네임 검색에서 연결된 모임원 정보까지 이동할 수 있게 한다.

## What Changes

- Vercel 연동으로 주입되는 `VALKEY_URL`의 TLS 연결을 서버에서 재사용한다.
- 로그인 상태를 매번 확인한 후 권한별로 투영한 게임 목록·상세, 모임원 목록·전적을 60초간 캐시한다.
- 데이터 변경 완료 후 캐시 세대를 교체하고, 연결 실패·미설정 시 PostgreSQL로 조회한다.
- 저장된 라이엇 계정을 검색하는 서버 함수와 결과 캐시, Valkey 접두어 자동완성을 추가한다.
- 랜딩 검색을 활성화하고 일치하는 닉네임의 연결 모임원으로 이동한다. 여러 모임원이 일치하면 선택 목록, 일치하는 연결이 없으면 없는 사용자 페이지를 제공한다.
- 환경별 키 공간과 연결·운영 검증 절차를 문서화한다.

## Capabilities

### New Capabilities

- `query-cache`: 선택적인 Valkey 조회 캐시, 권한 분리, 만료와 무효화, 장애 시 직접 조회.
- `nickname-search-foundation`: 저장된 계정 검색, 자동완성, 모임원 이동과 없는 사용자 페이지.

### Modified Capabilities

없음.

## Impact

조회 모델, 데이터 변경 트랜잭션과 리플레이 저장 완료 경로, 서버 전용 `ioredis` 연결 코드, 검색 화면·인증된 자동완성 API, 환경변수 예제와 운영 문서에 영향을 준다. 인증·관리자 자격증명·감사로그·요청 제한은 기존 PostgreSQL 경로를 유지한다. 외부 Riot API는 호출하지 않는다.
