## Context

최근 전적은 25경기씩 읽으며 전체 통계는 별도 집계한다. 참가자와 아이템·레벨 원본 값은 이미 저장돼 있다. 기존 화면의 파랑·빨강 배경과 회원 권한 경계를 유지한다.

## Goals / Non-Goals

**Goals:** 요청한 정보를 반응형 카드 행으로 제공하고 추가 DB 조회를 페이지당 한 번으로 제한한다.

**Non-Goals:** 티어·소환사 주문·평가 점수, 신규 Riot API 호출, DB 마이그레이션.

## Decisions

- 페이지 조회가 끝나면 해당 경기 ID만 `IN` 조건으로 참가자와 계정 이름을 일괄 조회한다. 기존 game_id 선두 복합 인덱스를 사용할 수 있으며, 빈 페이지는 추가 쿼리를 생략한다. 경기별 상세 조회는 사용하지 않는다.
- 다른 참가자는 이름·태그·챔피언·포지션·팀·본인 여부만 투영한다. 본인 참가자의 LEVEL과 ITEM0~6만 SQL에서 선택해 정규화한다. 원본 rawStats와 PUUID, 생년은 반환하지 않는다.
- 중복 연결 경기의 본인 레벨·아이템은 미확인으로 유지한다. 참가자 목록에서는 연결된 계정 모두를 표시한다. 누락된 팀은 별도 ‘팀 미확인’ 그룹으로 보존한다.
- 최근 경기 캐시 키를 `member-history-v2`로 변경해 이전 형식과 분리한다. 기존 60초 캐시와 쓰기 이후 무효화를 재사용한다.
- 카드와 팀 목록은 서버 컴포넌트로 렌더링한다. 이미지 오류 처리만 기존 클라이언트 아이콘으로 처리하며, 작은 CDN 이미지는 지연 로딩한다. 페이지의 경기 버전별 자산 요청을 묶고 기존 카탈로그 캐시를 공유한다.
- 큰 화면은 승패·날짜 / 초상화·레벨 / KDA·아이템 / 참가자 두 열 순서로 배치한다. 작은 화면은 참가자를 아래로 내려 가로 넘침을 방지한다.

## Risks / Trade-offs

- 참가자 수에 비례해 응답 크기 증가 → 현재 페이지와 표시 필드만 조회·캐시한다.
- 과거 리플레이 누락값과 CDN 실패 → 이름을 유지하고 레벨·슬롯을 미확인으로 표시한다.
- 로컬 DB 검사만으로 운영 지연 확정 불가 → 쿼리 수·범위를 회귀로 확인하고 로컬 검증과 운영 성능을 구분한다.

## Migration Plan

스키마 변경 없이 배포한다. 새 키가 기존 캐시와 공존하므로 코드 롤백 시 이전 키를 다시 사용할 수 있다.
