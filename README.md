# LLVY

리그 오브 레전드 소모임의 사용자 지정 게임 전적을 관리하기 위한 웹 앱입니다.

게임 클라이언트에서 내려 받을 수 있는 `.rofl` 리플레이 파일을 업로드하면 게임 정보와 참가자 전적을 추출해 보관합니다.
인게임 클라이언트에서 상세정보 보기에서 게임 ID를 확인 할 수 있어 파일명과 비교 후 필요한 파일을 사용하시면 됩니다.

현재 MVP 단계로서 정보를 수집하는 기능 위주로 구현하였습니다.

- 리플레이 업로드, 경기 목록·상세 조회, 중복 저장 방지
- 모임원 등록·수정·삭제와 Riot 계정·부계정 연결, 연결된 계정의 전적 합산
- 경기 제외·복구, 날짜 수정·원본 복원, 공백 포함 30자 코멘트
- 일반 조회·관리자·서비스 오너 권한 분리, 모임원별 관리자 키와 감사로그
- 라이엇 닉네임 접두어 자동완성과 연결된 모임원 전적 검색

Next.js App Router·TypeScript, Drizzle ORM·Postgres, Vercel Blob을 사용합니다.
현재 운영 배포는 Vercel을 전제로 합니다.

## 준비물

- Node.js 24.x와 npm
- 본인 소유의 Neon 데이터베이스와 Vercel Blob 스토어
- 업로드할 `.rofl` 파일

로컬에서 앱을 실행할 때도 DB와 Blob은 외부 서비스를 사용합니다. 개발용 리소스를
따로 준비하세요. 외부 서비스 연결 없이 코드만 검증하려면 `npm ci` 후 `npm run check`를
실행할 수 있습니다.

## 로컬에서 시작하기

```bash
npm ci
cp .env.example .env.local
```

`.env.local`에 아래 값을 설정합니다. Neon·Blob 연결은 [배포 안내](docs/deployment.md)를
참고하세요.

| 변수                       | 용도                                                                       |
| -------------------------- | -------------------------------------------------------------------------- |
| `READ_PASSWORD`            | 필수. 개인정보를 제한한 읽기 전용 공유 키                                  |
| `OWNER_PASSWORD`           | 필수. 서비스 오너 전용 키. 읽기 키와 다른 새 값                            |
| `POSTGRES_URL`             | 필수. Neon의 pooled 연결 문자열                                            |
| `POSTGRES_URL_NON_POOLING` | 마이그레이션용 direct 연결 문자열. 사용하지 않으면 예제의 줄을 삭제        |
| `BLOB_READ_WRITE_TOKEN`    | 필수. 본인 Blob 스토어의 read-write 토큰                                   |
| `BLOB_ACCESS`              | 스토어의 실제 접근 모드와 일치하도록 설정. 비공개 원본은 `private` 사용    |
| `AUTH_SECRET`              | 필수. 두 로그인 키와 다른 서버 전용 난수. `openssl rand -base64 32`로 생성 |
| `CRON_SECRET`              | 운영 배포 시 필요. 만료 업로드 정리 작업의 인증용 난수                     |

```bash
npm run db:migrate
npm run dev
```

[localhost:3000](http://localhost:3000)에 접속해 읽기 키 또는 서비스 오너 키로 로그인합니다.
같은 입력란에서 키에 따라 역할을 자동으로 판별합니다. `AUTH_SECRET`은 앞뒤 공백 제거 후
UTF-8 기준 32바이트 이상이어야 하며 사용자에게 공유하지 않습니다. 필수값 누락이나
키 중복, 짧은 서명 비밀값이 있으면 로그인을 허용하지 않습니다.

## 사용하기

1. 서비스 오너로 로그인해 **관리**에서 모임원을 등록합니다. 정보 수정 옆 **관리자로 지정**을
   누르면 16자 무작위 관리자 키가 한 번 표시됩니다. 복사해 해당 모임원에게 전달하세요.
   다시 조회하거나 재발급할 수 없으므로 분실하면 지정 취소 후 다시 지정합니다.
2. 관리자 또는 오너는 **업로드**에서 `.rofl` 파일을 선택합니다. 처리 후 경기 상세로 이동합니다.
   **관리**에서 리플레이로 발견한 계정을 연결하면 과거 경기도 모임원 전적에 반영됩니다.
3. **모임원**에서 부계정을 합친 승패·승률·평균 K/D/A와 경기별 전적을 확인합니다.
   플레이한 챔피언 표는 전체 활성 전적을 챔피언·포지션 조합별로 집계합니다. 같은 챔피언도
   포지션이 다르면 별도 행으로 표시하며, 포지션이 없는 경기는 ‘불명’으로 묶습니다.
   챔피언 표 아래의 **플레이 포지션** 표에서 포지션별 플레이 횟수와 승률을 확인합니다.
   승률은 승패가 결정된 경기 기준이며, 제외 경기와 계정 중복 연결 경기는 집계에서 제외합니다.
4. 관리자는 잘못 포함된 경기를 상세에서 제외하거나 복구하고, 부정확한 날짜를 수정합니다.
   경기 날짜에는 시간을 저장하지 않으며 코멘트도 남기고 수정할 수 있습니다.
   제외해도 원본 파일과 참가자 기록은 보존됩니다. 제외 경기에서만 발견한 계정은 미연결 목록에 표시하지 않습니다.
5. **관리**의 모임원·미연결 계정 표는 각각 10개씩 표시합니다. 관리자도 모임원을 실제로 삭제할 수 있습니다.
   활성 관리자는 먼저 오너가 지정 취소해야 삭제할 수 있고, 삭제한 모임원의 계정은 연결이 해제됩니다.

| 기능                                       | 일반 사용자           | 관리자    | 서비스 오너 |
| ------------------------------------------ | --------------------- | --------- | ----------- |
| 경기·통계·모임원 조회                      | 허용                  | 허용      | 허용        |
| 모임원 이름·생년                           | 이름 마스킹·생년 숨김 | 전체 표시 | 전체 표시   |
| 리플레이 업로드·처리                       | 차단                  | 허용      | 허용        |
| 모임원 추가·수정·삭제, 계정 연결·해제      | 차단                  | 허용      | 허용        |
| 경기 날짜·코멘트 수정, 원본 복원·제외·복구 | 차단                  | 허용      | 허용        |
| 관리자 지정·지정 취소                      | 차단                  | 차단      | 허용        |
| 감사로그 조회                              | 차단                  | 차단      | 허용        |

일반 사용자의 첫 화면에서 라이엇 닉네임을 검색할 수 있습니다. 입력 중에는 모임원에 연결되고
활성 경기 기록이 있는 계정만 최대 10개 추천합니다. 검색은 닉네임 전체와 선택한 `#태그`를
현재 연결로 확인하고, 한 모임원은 전적으로 이동하며 동명 모임원은 선택하게 합니다.
없는 계정·미연결 계정은 없는 사용자로 안내합니다. NFC·대소문자·태그 접두어를 지원하며
초성·오타 보정은 지원하지 않습니다.

일반 사용자에게는 게임·모임원 메뉴만 표시하고, 직접 업로드·변경 요청도 서버에서 거부합니다.
이름은 `김길수 → 김*수`, `홍길동철 → 홍**철`, 외자는 `김수 → 김*`로 표시하며 생년은
브라우저에 전달하지 않습니다. 현재 이름 문자열로는 복성을 별도로 구분하지 않습니다.

관리자 키는 모임원별로 발급하며 DB에는 SHA-256 해시만 저장합니다. 취소가 끝나면 기존 키와
세션은 사용할 수 없고, 다시 지정해도 이전 키·세션은 복구되지 않습니다. 키를 다른 사람에게
전달하면 그 사람이 한 작업도 해당 모임원 명의로 기록됩니다. 로그인 사건과 데이터 변경을
감사로그에 남기며 **오너만 관리 화면에서 조회**할 수 있습니다.

업데이트에는 DB 마이그레이션과 새 환경변수 설정이 필요하고 기존 세션은 모두 종료됩니다.
`READ_PASSWORD` 교체는 일반 사용자 세션, `OWNER_PASSWORD` 교체는 오너 세션,
`AUTH_SECRET` 교체는 모든 세션을 무효화합니다. [배포 안내](docs/deployment.md#권한-분리-업데이트와-키-교체)를
따라 기존 공유 관리자 키를 폐기하고 새 오너 키를 설정하세요.

## 주요 제한

- 파일은 최대 64MiB, 참가자는 최대 10명까지 처리합니다. 참가자 통계가 없는 파일은 거부합니다.
- 업로드 시작은 세션별 24시간에 10회, 전체 50회까지 허용합니다.
- 실제 검증 표본은 패치 `16.19.821.7343`의 솔랭 리플레이입니다. 다른 패치와 사용자설정
  게임, 비표준 조합의 포지션 정확도는 별도 확인이 필요합니다.
- 경기 날짜는 파일 수정 시각의 한국 날짜를 사용하고, 없으면 업로드한 한국 날짜를 사용합니다.
  정확한 날짜는 경기 상세에서 직접 수정할 수 있습니다.
- `public` Blob은 URL을 아는 사람이 원본을 읽을 수 있습니다. 비공개 원본을 보관하려면
  private 스토어를 만들고 `BLOB_ACCESS=private`로 설정하세요.
- Vercel 외의 운영 호스팅은 신뢰할 수 있는 클라이언트 IP 처리 등 코드 변경이 필요합니다.
  자세한 조건은 [배포 안내](docs/deployment.md#다른-환경에서-실행할-때)를 참고하세요.
